# Безопасность DotLink

Пульт даёт полный контроль над ПК, поэтому защита рассчитана на чужих в той же Wi-Fi сети.

## Что защищено

- **Прямые подключения — только из локальной сети.** Сервер отвечает лишь на подключения с частных, link-local, CGNAT и петлевых адресов. Из интернета ПК доступен только через ретранслятор, к которому ПК подключается сам (исходящее соединение, без открытых портов).
- **Ретранслятор — без доверия.** Он видит только факт и объём связи: вход телефона — вызов-ответ по ключу устройства, дальше — тот же шифрованный канал, что и в сети. Выдать себя за ПК он не может (ПК доказывает знание ключа устройства), прочитать или подменить кадры — тоже. Комната — хэш секрета ПК: ретранслятор проверяет владение, ничего не храня. Сопряжение по PIN через ретранслятор запрещено (см. ниже), по QR — можно.
- **Bluetooth.** RFCOMM без сопряжения Bluetooth («insecure»), но поверх — та же сессия DotLink: вход по ключу и XChaCha20-Poly1305.
- **WebRTC.** Сигналинг (SDP, ICE) идёт внутри шифрованной сессии, поэтому подменить его по дороге нельзя. Кадры DataChannel, кроме DTLS, шифруются ключами сессии с отдельными метками для каждого канала.
- **Сопряжение по QR.** Секрет 128 бит виден только на экране ПК. Телефон и ПК обмениваются ключами X25519 и доказывают знание секрета HMAC-ом, привязанным к обмену. Перехват не даёт ключа, подмена (MITM) без секрета невозможна. QR одноразовый и живёт 3 минуты.
- **Вход.** Долгоживущий ключ устройства не передаётся: вход — вызов-ответ HMAC со случайными nonce обеих сторон. ПК тоже доказывает знание ключа, так что телефон не подключится к поддельному ПК.
- **Канал.** XChaCha20-Poly1305: свои ключи и префиксы nonce на каждое направление, счётчик против повторов. Нажатия нельзя ни прочитать, ни подделать.
- **Права.** На ПК для каждого устройства: ввод, медиа, питание, макросы, буфер, файлы. Отключение устройства сразу закрывает его сессию и удаляет ключ.
- **Управление телефоном с ПК.** Возможно только при включённой вручную службе специальных возможностей DotLink и только от ПК, с которым телефон сопряжён и сейчас соединён. Трансляцию экрана Android подтверждает человек на каждый сеанс, а значок записи виден в шторке, пока она идёт. Кадры экрана уходят только дашборду на этом ПК.
- **Мышь ПК на телефоне.** Хуки Windows пропускают события, введённые программами (флаг injected), и всегда отдают Windows отпускание модификаторов — клавиши не «залипают». Esc сразу возвращает мышь.
- **Дашборд.** Служебное подключение — только с 127.0.0.1 и со случайным токеном, который знает лишь окно DotLink. Загрузка в «исходящие» — тоже по токену.
- **Файлы.** Билеты одноразовые и живут 2 минуты. Имена очищаются от путей и зарезервированных имён Windows, существующие файлы не перезаписываются.

## Известные компромиссы

- **PIN слабее QR.** Шесть цифр защищают от случайного подключения: после пяти ошибок PIN меняется. Но активный атакующий, который перехватит обмен во время сопряжения, может подобрать PIN офлайн. Поэтому через ретранслятор PIN не принимается вовсе, а для надёжного сопряжения стоит использовать QR.
- **Тело файлов по Wi-Fi не шифруется DotLink.** В локальной сети файлы идут обычным HTTP по одноразовой ссылке — ради скорости и нативного скачивания; эфир WPA2/WPA3 шифрует сама Wi-Fi. Через ретранслятор и Bluetooth файлы идут внутри шифрованной сессии. Буфер обмена, ввод, уведомления, экран телефона и состояние всегда идут только по шифрованному каналу.
- **Уведомления телефона** пересылаются на ПК (заголовок и текст), пока телефон подключён и пересылка включена; в дашборде хранятся последние 30, только в памяти.
- **Хранение ключей.** Ключи устройств лежат в `%APPDATA%\DotLink\config.json` (доступ — у пользователя Windows), на телефоне — в хранилище приложения или браузера.
- **Макросы PowerShell** выполняют то, что вы в них записали. Право «Макросы» можно выключить для отдельного устройства.
