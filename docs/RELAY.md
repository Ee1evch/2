# Свой ретранслятор

Ретранслятор нужен, когда телефон и ПК в разных сетях: телефон в мобильном интернете, ПК дома за роутером. ПК держит к ретранслятору исходящее соединение, телефон приходит туда же, ретранслятор сшивает два WebSocket. Чаще всего после этого телефон и ПК соединяются напрямую по WebRTC (сквозь NAT через STUN), и ретранслятор остаётся запасным путём.

Ретранслятор ничего не хранит и не видит содержимого: вход и шифрование — сквозные, как в локальной сети (подробно — [SECURITY.md](SECURITY.md)).

## Быстрый запуск (VPS + домен)

Нужен сервер с публичным IP и домен, указывающий на него (A-запись). Caddy сам получит сертификат Let's Encrypt.

```bash
git clone https://github.com/Ee1evch/2 dotlink && cd dotlink
RELAY_DOMAIN=relay.example.com docker compose -f deploy/relay/docker-compose.yml up -d
curl https://relay.example.com/healthz     # ok rooms=0 pipes=0 …
```

В DotLink на ПК: **Настройки → Связь из любой сети → Ретранслятор**: `wss://relay.example.com`. Статус рядом с полем станет «Комната открыта». Телефоны, уже сопряжённые с этим ПК, получат новый маршрут сами при следующем подключении по Wi-Fi; новый QR содержит его сразу.

## Без Docker

```bash
cargo build --release -p dotlink-relay
./target/release/dotlink-relay --listen 127.0.0.1:47900 --max-pipes 8 --rate-mbit 64
```

TLS — обратным прокси (Caddy, nginx) с поддержкой WebSocket. Пример для Caddy — `deploy/relay/Caddyfile`. Для проверки в своей сети можно и без TLS: `ws://192.168.1.10:47900` (приложение для Android и PWA с ПК это допускают).

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--listen` / `DOTLINK_RELAY_LISTEN` / `PORT` | `0.0.0.0:47900` | адрес и порт |
| `--max-rooms` | 10 000 | сколько ПК одновременно |
| `--max-pipes` | 8 | сколько телефонов одновременно на один ПК |
| `--rate-mbit` | 64 | предел скорости на трубу в каждую сторону |

## STUN и TURN

По умолчанию ПК и телефон используют публичные STUN (Google, Cloudflare) — этого хватает для большинства домашних и мобильных сетей. Если с обеих сторон симметричный NAT (некоторые корпоративные сети и операторы), прямой канал не поднимется и связь пойдёт через ретранслятор — это работает, просто медленнее. Чтобы и в таких сетях был прямой UDP, поднимите TURN (например, coturn) и добавьте его в **Настройки → STUN / TURN** строкой `turn:логин:пароль@turn.example.com:3478`.

## Как это устроено

- Комната — `base64url(SHA-256("dotlink/relay-room/v1" ‖ секрет)[0..16])`; секрет хранится только на ПК (`config.json`). Ретранслятор проверяет владение комнатой, вычисляя хэш присланного секрета.
- `GET /v1/pc/<комната>?secret=…` — управление: ретранслятор сообщает `{"t":"incoming","sid":…}`, когда приходит телефон.
- `GET /v1/pc/<комната>/<sid>?secret=…` — труба ПК для этого телефона.
- `GET /v1/phone/<комната>` — труба телефона; `404`, если ПК не в сети, — телефон сразу пробует другие пути.
- Новое подключение того же ПК вытесняет старое (перезапуск, смена сети).
